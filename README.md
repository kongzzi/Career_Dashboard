# 커리어 대시보드

강의·컨설팅·프로젝트의 일정과 수입을 **엑셀 한 파일**로 관리하고, 웹 화면으로 들여다보는 1인용 로컬 도구.

## 실행

```bash
python3 run.py
```

엑셀 파일이 없으면 만들고, 로컬 서버를 띄운 뒤 브라우저를 엽니다.
종료는 터미널에서 `Ctrl+C`. 서버는 `127.0.0.1`에만 열려 외부에서는 접근할 수 없습니다.

처음 한 번만:

```bash
python3 -m pip install -r requirements.txt
```

프런트엔드는 빌드도 의존성도 없습니다 — 순수 ES 모듈과 손으로 그린 SVG뿐이라
npm 도 CDN 도 끼어들지 않습니다(그래서 오프라인에서 그대로 돕니다).

## 데이터

모든 내용은 `data/career.xlsx` **한 파일**에 들어갑니다. 데이터베이스는 쓰지 않습니다.

| 시트 | 한 행의 의미 | 비고 |
|---|---|---|
| `일감` | 계약·의뢰 1건 | 46개 칸 |
| `강의배정` | 과목·분반 1개 | 일감 1건에 여러 행 |
| `월급여` | 한 달치 급여 | 월정액 계약에만 |
| `기관` | 거래처 1곳 | 기본단가·지역 자동완성용 |
| `설정` | 기본값과 드롭다운 목록 | 4대보험 요율도 여기 |

- 엑셀에서 직접 편집해도 됩니다. 편집 후 대시보드 상단 **↻** 로 다시 읽습니다.
- 저장할 때마다 직전 파일이 `data/backups/` 에 보관됩니다(최근 10개).
- **엑셀로 파일을 열어 둔 상태에서는 대시보드가 저장하지 못합니다.** 저장 전에 닫아 주세요.
- `설정` 시트의 `목록` 행을 추가하면 드롭다운 선택지가 늘어납니다.
- 모든 시트를 **헤더 이름**으로 읽으므로, 컬럼이 늘어나도 예전 파일이 깨지지 않습니다.

### 입력 폼은 필요한 칸만 보여줍니다

46개 칸이 전부 뜨지 않습니다. 급여방식·강의형태·진행방식에 따라 안 쓰는 칸이 접힙니다
(온라인 단기특강이면 25칸). **값이 들어 있는 칸은 절대 숨기지 않고**, 폼 아래
`쓰지 않는 항목까지 모두 보기`로 언제든 전부 펼칠 수 있습니다.

## 계산 규칙

필드가 서로 얽혀 있으니, 계산을 건드리기 전에 이 절을 먼저 읽으세요.

### 금액

- **급여방식** — 총액을 어떻게 구할지 정합니다.
  - `시간급` — `총시수 × 시간당단가` (기본값)
  - `월정액(연봉제)` — `월 지급액 × 계약 개월수`. **계약 연봉**을 넣으면 월 지급액이 12분의 1로 자동 계산됩니다.
  - `총액 일괄` — 총액 직접 입력 (교재 집필, 시스템 구축 등)
- **총액(세전)** — 급여방식대로 자동 계산되어 시트에도 기록됩니다. 직접 넣으면 그 값이 우선입니다.
- **세금적용** — 건마다 고릅니다.

  | 선택 | 공제 |
  |---|---|
  | `사업소득 3.3%` / `기타소득 8.8%` | 해당 요율 |
  | `4대보험 (근로소득)` | 국민연금·건강보험·장기요양·고용보험을 **월 급여 기준으로 계산 후 개월수만큼** |
  | `미적용 (세금 없음)` | 없음 |
  | `직접입력` | 원천징수율 칸의 값 |

  앞의 넷을 고르면 원천징수율 칸이 자동으로 채워지고 잠깁니다.
  4대보험 요율은 **설정 > 4대보험 요율**에서 고칩니다 — 해마다 바뀌니 확인하고 쓰세요.
  소득세는 간이세액표라 정확히 계산할 수 없어 기본 0%이며, 아래 *월 실수령액*을 쓰는 편이 정확합니다.
- **월 실수령액** — 급여명세서의 실수령액. 넣으면 **공제 계산보다 우선**하고 공제액은 역산됩니다.

### 경비

- **경비지급방식**

  | 선택 | 뜻 |
  |---|---|
  | `강사료와 함께` | 강사료 정산상태를 그대로 따라감 (기본값) |
  | `별도 지급` | 경비만 따로 `미청구/청구/입금완료`와 입금일 추적 |
  | `자부담` | 내 부담 — 실수령에서 차감 |
  | `해당없음` | 경비 없음 |

- **실수령 예상** = `총액 − 공제 − 자부담 경비`. 받기로 한 경비는 통과금이라 실수령을 늘리지 않습니다.
- **입금 예상** = `세후 강사료 + 받기로 한 경비`. 통장에 찍힐 금액이라 *실수령 예상*과 다릅니다.

### 실제 입금

- **실입금액** — 통장에 찍힌 금액을 **그대로** 적습니다. 비우면 예상액을 씁니다.
  경비지급방식이 `강사료와 함께`면 한 번에 들어오므로 이 칸이 **합산 금액**을 뜻합니다
  (라벨도 `실입금액 (강사료+경비)`로 바뀝니다). **경비를 손으로 빼지 마세요.**
- **경비 실입금액** — `별도 지급`일 때만 씁니다.
- **부분 입금** — 정산상태가 `청구`인데 실입금액이 있으면 차액만 미수금으로 남습니다.
- **받을 돈** = 미입금 강사료(세후) + 아직 못 받은 경비.

### 일정

위에서부터 먼저 맞는 것 하나만 적용됩니다.

1. `강의배정`에 과목이 있으면 → **개강일부터 주차만큼** (분반별로 각각)
2. `개별 날짜`가 있으면 → 적힌 날들 (띄엄띄엄한 특강·격주)
3. `요일`이 있으면 → 시작일~종료일 사이 해당 요일마다
4. 둘 다 없고 기간이 31일 이내면 → 그 사이 매일
5. 그 외 → 시작일 하루 (장기 프로젝트 — 기간은 타임라인이 보여줌)

`개별 날짜`는 `2026-08-10, 08-17, 24` 처럼 연·월을 이어받는 축약도 됩니다.
저장하면 정렬·중복제거되고 시작일·종료일이 자동으로 맞춰집니다.

### 수입 귀속

- 상단 토글: **입금기준**(기본, 입금일에 귀속) / **발생기준**(수업일에 귀속)
- 금액은 항상 **실입금 기준** — 적어 넣은 실수령액이 있으면 그 값을, 없으면 세후 추정치를 씁니다.
  **세전 계산값은 옆에 참고로** 표시되고, 몇 달치가 추정인지도 알려줍니다.
- **월정액은 수업이 주 2회여도 수입은 달마다** 잡힙니다. 캘린더엔 수업이 그대로 뜨고,
  월별 수입 차트에만 달 단위로 반영됩니다.
- **집계 대상 상태** — `확정`·`진행중`·`완료`. `문의`는 "가망"으로 따로, `취소`는 제외.
- **실효 시간당 단가** — `실수령 ÷ 시수`. **월정액은 제외**합니다(계약이 시간 기준이 아니므로).

## 강의배정 (과목·분반)

한 계약에서 여러 과목·분반을 맡을 때, 분반마다 요일·시각·시수가 다르므로 행으로 나눠 적습니다.

| 칸 | 뜻 |
|---|---|
| 학기 | `1학기` / `2학기` / `여름계절` / `겨울계절` |
| 과목명 · 분반 | `AI 이해와 활용` · `1분반` |
| 요일 · 시작/종료시각 | `월,수` · `10:00`–`12:00` |
| 주당시수 | 그 분반의 한 주 수업 시간 |
| **개강일 · 주차** | **달력에 뿌리는 기준** — 개강일부터 N주 (기본 15) |
| 대상 · 인원 · 강의실 · 비고 | 분반마다 다를 수 있습니다 |

- **수업은 개강일부터 주차만큼만 표시됩니다.** 계약이 1년이어도 1학기 과목은 15주로 끝납니다.
  개강일을 비우면 일감의 시작일을, 주차를 비우면 15주를 씁니다.
- 과목을 추가하면 **앞 행의 학기·개강일·주차를 물려받습니다.**
- **공휴일 휴강은 반영하지 않습니다.** 월급에 영향이 없기 때문입니다.
  필요하면 `비고`에 적어두세요(달력 툴팁에 함께 뜹니다).
- 총시수를 비우면 `주당시수 × 주차`로 자동 계산됩니다.

## 월급여 (연봉제)

월정액 계약은 달마다 돈이 들어오므로 달별 행을 둡니다.

| 칸 | 뜻 |
|---|---|
| 년월 | `2026-09` |
| 지급예정(세전) | 계약에서 자동 생성 |
| 공제액 · 실수령액 | 급여명세서를 보고 채웁니다 (실수령액만 넣어도 됨) |
| 입금일 · 상태 | `예정` / `입금완료` |

- 월정액 계약을 저장하면 **달별 행이 자동 생성**됩니다.
- **행이 있으면 그 값이 계약의 추정치를 대신합니다.** 총액은 행 합계가 되고,
  월별 수입은 달마다 실제 금액으로 잡히며(일할·상여로 달라도 정확), 받을 돈은 아직 `예정`인 달의 합입니다.
- 실수령을 안 적은 달은 그 달 지급액 기준으로 추정합니다.
- *계약 기간으로 다시 생성* 은 기간이 바뀌었을 때 씁니다 —
  **이미 `입금완료`이거나 실수령액을 채운 달은 건드리지 않습니다.**

## 구조

```
run.py                  실행기 — 엑셀 준비 → 로컬 서버 → 브라우저
server/schema.py        ★ 스키마 단일 정의 (엑셀 헤더 = 웹 폼)
server/store.py         엑셀 읽기/쓰기, 백업, 정규화
server/app.py           FastAPI (127.0.0.1 전용)
web/js/core.js          ★ 상태 + 파생 계산 — 금액·일정 로직의 심장
web/js/charts.js        손으로 그린 SVG 차트 (외부 라이브러리 없음)
web/js/{dashboard,schedule,records,settings}.js   화면별 렌더러
data/career.xlsx        데이터 원본
```

컬럼을 추가하려면 `server/schema.py` 의 `FIELDS` 에 한 줄. 엑셀 헤더·입력 폼·표가 따라옵니다.

## 테스트

```bash
./run_tests.sh
```

계산 규칙이 촘촘해서 한 곳을 고치면 다른 곳이 조용히 틀어집니다. 그 지점들을 묶어 뒀습니다.

| 파일 | 대상 | 도구 |
|---|---|---|
| `tests/test_store.py` | 날짜 파싱, 총액 자동 계산, 엑셀 읽기/쓰기, 스키마 무결성 | `python3 -m unittest discover -s tests` |
| `tests/test_core.mjs` | `derive` · `sessionsOf` · `incomeSchedule` — 금액과 일정 | `node --test "tests/**/*.mjs"` |

- 추가 설치가 필요 없습니다. 파이썬은 표준 `unittest`, 자바스크립트는 Node 내장 `--test`.
- 기대값은 **손으로 계산해 주석에 근거를 남겨** 뒀습니다. 숫자가 안 맞으면 코드부터 고치지 말고
  주석의 계산을 먼저 읽고 어느 쪽이 틀렸는지 판단하세요.
- 지금까지 실제로 겪은 버그(경비 이중 계산, 컬럼 밀림, 상여 달 추정 오류, 학기 밖으로 새는 수업)가
  전부 회귀 테스트로 들어가 있습니다.
- **사용자의 `data/career.xlsx` 는 읽기만 합니다.** 쓰기 테스트는 임시 폴더 안에서만 돌고,
  마지막에 실데이터가 그대로인지 스스로 확인합니다.
